# База знаний в боте — состояние и что дорабатывать

Дата: 2026-08-11 · ветка доработки: `feat/kb-bot-v2` (от `1ea3c87`)
Спека первой версии: `docs/superpowers/specs/2026-08-10-bot-knowledge-base-design.md`

## Что уже работает (в проде)

Ученик пишет @testtoyzbot вопрос в личку → бот отвечает 2-3 предложениями строго
из материалов Саши и даёт кнопку прямо в нужный материал.

| файл | за что отвечает |
|---|---|
| `src/lib/kb/map.ts` | карта из 61 материала, HTML → текст, текст материала, `visibleTo`/`isOpen` |
| `src/lib/kb/tier.ts` | `tierFromSlug`, тарифы по telegram id (роль без тарифа = 0) |
| `src/lib/kb/answer.ts` | два обращения к модели: выбор по карте → ответ по тексту |
| `src/lib/kb/ask.ts` | ветка бота: лимиты, ответ, кнопка, логи |
| `src/content/workshops/index.ts` | сгенерированный текст воркшопов (не править руками) |
| `scripts/kb-eval.ts` | прогон без бота |
| `GSD-BRAND/scripts/workshops-to-kb.mjs` | сборщик текстов воркшопов из React-страниц |

**Разделы карты:** курс 10 · промпты 7 · «Поток спроса» 3 · «Формула» 24 ·
воркшопы 14 · разборы 1 · созвоны 2.

**Проверка:**
```bash
cd Projects/TheSasha/quiz-app
npx tsx scripts/kb-eval.ts --map        # карта, без обращений к модели
npx tsx scripts/kb-eval.ts --window     # ловится ли нарезка по блокам
npx tsx scripts/kb-eval.ts              # 13 вопросов, последний прогон 12/13
npx tsx scripts/kb-eval.ts "свой вопрос"
```
Прогон печатает токены и цену: сейчас **0,69 ¢ за вопрос**. Единственный
неполный исход — «воркшопы тарифу 1 закрыты»: бот честно молчит, а кейс ждёт
ответ. Это дефект самого кейса, не бота.

Прогон на проде делается так: слать вебхуку апдейт, где `from.id` — реальный
аккаунт с доступом, а `chat.id` — несуществующий чат. Бот отработает целиком,
отправка упадёт с «chat not found», живых людей это не заденет. Тестовые записи
потом удалить из `events`.

## Дорабатывать — по убыванию важности

### 1. ✅ Секрет вебхука — сделано 11.08 (`f17d13f`)
`api/telegram-webhook` принимал любой POST с валидным JSON. Теперь в начале
роута сверяется заголовок `X-Telegram-Bot-Api-Secret-Token` — чужой запрос
отбивается 401 **до чтения тела**, то есть без записей в базу и без обращений
к модели.

Секрет живёт в `TELEGRAM_WEBHOOK_SECRET` (`.env.local` + Vercel: production,
preview, development). Проверка мягкая: переменной нет — пускаем всех, как
раньше. Это окно на раскатку, а не запасной вход: в проде переменная задана.

```bash
node scripts/set-webhook.mjs status   # что стоит сейчас
node scripts/set-webhook.mjs gen      # новый секрет
node scripts/set-webhook.mjs set      # поставить вебхук с secret_token
```

⚠️ **Порядок при смене секрета — сначала Телеграм, потом деплой.** Если сперва
уедет код с новым значением, роут начнёт отдавать 401 на настоящие апдейты, и
бот замолчит до `set`. В обратном порядке простоя нет: старый код лишний
заголовок просто игнорирует. Апдейты при этом не теряются — Телеграм ретраит
всё, на что не получил 2xx.

### 2. ✅ Стоимость — сделано 11.08 (`84542e3`, `86de289`)

Вопрос стоил около 1,7 ¢ (оглавление 10 400 токенов + материал целиком до
12 500). Стало **0,69 ¢** — при сотне вопросов в день это ~20 $/мес вместо
50-60. Точность не изменилась: eval как был 12 из 13.

Три вещи, каждая независимо:

1. **Часовой кэш на оглавление.** Пятиминутный по умолчанию не доживал до
   следующего вопроса, и каждый платил за карту заново. Запись в часовой стоит
   вдвое, чтение — десятую часть.
   ⚠️ Окупается **от трёх вопросов в час**. При потоке реже часовой кэш
   немного дороже, чем совсем без кэша (переплата за запись) — суммы копеечные,
   но если бот так и не разойдётся, дешевле вернуть `ttl` к пяти минутам.
2. **Оглавление режется по бюджету знаков**, а не по числу заголовков
   (`NOTE_BUDGET`, `HEADINGS_BUDGET`, `HEADING_MAX` в `map.ts`): у воркшопов
   заголовки длинные и их полсотни, у уроков короткие и их десяток. Тариф 2:
   10 430 → 7 074 токена, тариф 1: 6 047 → 4 605.
   ⚠️ **Минимум кэша на Haiku 4.5 — 4096 токенов.** Тариф 1 идёт впритык: ужмёшь
   карту сильнее — кэш перестанет работать молча, без ошибки.
3. **Ответ по блоку, а не по всему материалу.** Шаг выбора и так читает
   заголовки блоков, поэтому он теперь называет и блок; на шаг ответа едет окно
   вокруг него (`textAround`). Не хватило окна — тот же вопрос повторяется по
   полному тексту, так что ответ не теряется, а лишнее обращение платится редко.

Проверять после правок материалов:
```bash
npx tsx scripts/kb-eval.ts --window   # ловятся ли заголовки: сейчас 874 из 874
```
Промах не ломает ответ, но материал уедет целиком и вопрос станет втрое дороже.

Токены и цена каждого вопроса пишутся в `events` (`tokIn`, `tokCacheRead`,
`tokCacheWrite`, `tokOut`, `cents` в `metadata`):
```sql
SELECT date_trunc('day', created_at) d, count(*), round(sum((metadata->>'cents')::numeric), 1) cents
FROM events WHERE type IN ('kb_question','kb_gap') GROUP BY 1 ORDER BY 1 DESC;
```

Что осталось из идей, если поток вырастет: двухуровневый выбор (сначала раздел,
потом материал внутри) — сожмёт шаг выбора ещё вдвое ценой третьего обращения.

### 3. Голосовые вопросы
Сейчас база знаний берёт только текст: голос, кружки и файлы занимает анкета
тарифа 3, и пересечение сломало бы обе ветки. Развести можно по состоянию
анкеты: нет активной анкеты → голос идёт в базу знаний через Whisper
(`src/lib/whisper.ts` уже есть).

### 4. Ссылка на блок внутри материала
Кнопка открывает материал целиком; модель называет блок словами, но якоря нет.
У статей курса есть `<h2>`/`<h3>` — можно проставлять `id` и вести на `#anchor`.

### 5. Обратная связь на ответ
Две кнопки «помог / не помог» под ответом → событие в `events`. Это единственный
способ отличить «ответил и попал» от «ответил мимо»: сейчас в логах только сам
факт ответа.

### 6. Разбор дыр
Раз в неделю смотреть, чего людям не хватило:
```sql
SELECT metadata->>'question' FROM events WHERE type = 'kb_gap' ORDER BY created_at DESC;
```
Это готовые темы для уроков и созвонов.

### 7. Пересборка воркшопов вручную
`workshops-to-kb.mjs` гоняется руками. Правку воркшопа легко забыть перенести —
бот будет отвечать по старому тексту. Стоит цеплять сборку к деплою `dashboard`
или проверять свежесть модуля в CI.

### 8. Не входит пока
Статьи, подкасты, Ютуб. Меняется только сборщик карты — механика та же, что
у воркшопов.

## Грабли, которые уже наступили (не повторять)

1. **Шаг выбора возвращал метку целиком** (`kurs/02-uroven-1`) в оба поля
   `section` и `slug` — поиск не находил совпадений, и бот на всё отвечал
   «этого в материалах нет», хотя материал подбирал правильный. Симптом
   обманчивый: выглядит как «модель не знает». Лечится одним полем `id`.
2. **Имена участников лезут в названия блоков** («Даша: не вываливать оффер
   сразу»). Промпта мало — заголовок копируется дословно. Чистка кодом:
   `stripPeople()` по `participants` материала.
3. **Роли без тарифа терялись.** `sync` не имеет суффикса `-tN`, старый расчёт
   его выбрасывал — по «Синхронизации» не открылось бы ничего.
4. **Библиотека воркшопов открыта с тарифа 2, а не 3** — память отставала от
   кода (`b5f9aa4`). Правило берётся из `gated.tsx` каждой страницы.
5. **Ключ `ANTHROPIC_API_KEY` в `reels-optimizer/.env` протух** (401). Живой —
   в `brand-quiz/.env.local`, он же прописан в quiz-app и в Vercel.
6. **`dotenv` в скрипте не поможет клиенту, созданному на уровне модуля** —
   импорты выполняются раньше. Клиент Anthropic создаётся лениво.
