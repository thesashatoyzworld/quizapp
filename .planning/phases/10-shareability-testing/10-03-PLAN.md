<task type="auto">
  <name>Task 2: Perform codebase-level UX audit and create audit report</name>
  <files>
    .planning/phases/10-shareability-testing/10-03-UX-AUDIT.md
  </files>
  <action>
    Perform a systematic UX audit by reading the codebase. This is what the AI CAN do — analyze code for UX issues without needing to run the app.

    Read and analyze these files for UX issues:

    1. **page.tsx** — Quiz flow state machine:
       - Are all state transitions correct? (welcome -> quiz -> result-preview -> analyzing -> result -> payment-success)
       - Is there a way to go back? Should there be?
       - What happens on page refresh? Is state persisted?
       - Error handling: what if API calls fail?

    2. **All 5 result components** — Content and layout:
       - Is the reading flow logical? (hero -> diagnostics -> reasons -> case study -> CTA)
       - Are there too many scroll sections before CTA?
       - Is the CTA prominent enough?
       - Are there any dead ends (sections with no clear next action)?

    3. **useTelegram.ts** — Telegram integration:
       - Edge cases: what if Telegram WebApp is unavailable?
       - Is `user.first_name` always available?
       - Does `sendCallback` handle errors gracefully?

    4. **API routes** — Reliability:
       - check-subscription: what if Telegram API is slow/down?
       - prodamus-webhook: is it secured properly?
       - track-event: does it fail silently?

    5. **CSS/globals.css** — Visual issues:
       - Are there any z-index conflicts?
       - Font loading: what if custom fonts fail?
       - Are touch targets large enough (min 44px)?

    6. **Share flow** (from Plan 10-01):
       - What if html-to-image fails (certain CSS not supported)?
       - What if Web Share API not available?
       - What if screenshot is too large?

    For each issue found, document:
    - **Category:** Critical / Major / Minor
    - **Location:** File path and line range
    - **Issue:** What's wrong
    - **Impact:** How it affects users
    - **Fix:** Specific code change recommendation

    Group findings into sections:
    - Critical (blocks user journey)
    - Major (degrades experience significantly)
    - Minor (cosmetic or edge case)
    - Recommendations (improvements, not bugs)

    This produces a prioritized list for TEST-04 (iteration round).
  </action>

    - Contains categorized findings (Critical/Major/Minor/Recommendations)
    - Each finding has location, issue, impact, and fix
    - At least 5 findings documented
    - Findings reference actual file paths and code patterns
  </verify>
