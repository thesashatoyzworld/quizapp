# Помощник в продажах: разбор входящих и суфлёр

Дата: 2026-09-01. Статус: дизайн согласован, план не написан.

## Почему порядок именно такой

Разведка по ChatPlace 01.09.2026, 291 диалог за семь дней:

| Что | Сколько |
|---|---|
| Диалогов всего за неделю | 291, около 40 в день |
| Получили живой ответ (от нас больше двух сообщений) | 59, это 20% |
| Только автоответ воронки, живого диалога не было | 232, это 80% |
| Написали по существу и ждут ответа | 84 |
| Из них ждут дольше суток | 33, причём 26 висят от трёх до семи дней |

Внутри зависших: двое спросили цену прямым текстом («Подскажите
стоимость личной работы», «Интересно узнать о стоимости услуг») и не получили
ответа; один человек пять дней ждёт ссылку на лид-магнит, которая не пришла;
несколько написали развёрнуто про свою ситуацию.

**Вывод:** суфлёр «что писать дальше» обслуживает 59 переписок в неделю,
список неотвеченных обслуживает 232. Сначала строим второе.

Это совпадает с методом из кейса Васи: каждый лайк это повод для диалога,
конверсия таких диалогов около 80%. Сейчас 80% написавших не получают ответа.

## End Goal

Ассистент открывает список и видит, кому писать прямо сейчас: кто написал по
существу, сколько ждёт, о чём. Дальше спрашивает помощника «что ему писать»
и получает готовый текст, собранный по живой переписке, профилю человека и
системе продаж Саши.

## Порядок работ

### Этап 0. Разбор входящих

Отвечает на вопрос «кому писать». Самостоятельная ценность, не требует ни
модели для генерации, ни базы знаний.

- Проход по чатам ChatPlace, у каждого определяется, кто написал последним
- Отсев мусора правилами: эмодзи, реакции на сторис, короткие «спасибо»
- Приоритет оставшихся: вопрос про цену и про работу выше развёрнутого
  рассказа о себе, развёрнутый рассказ выше реплики про контент
- Сортировка по давности внутри приоритета
- Показ: новая вкладка «Ждут ответа» в существующем `/admin/instagram`

Приоритет считается на Haiku: содержательных сообщений около 12 в день,
стоимость незаметна. Правила отсеивают мусор до модели.

**Готово, когда** ассистент может открыть вкладку и сверху увидеть человека,
который вчера спросил цену.

### Этап 1. Суфлёр через MCP, для Саши

Отвечает на вопрос «что писать». Проверяется Сашей лично, до того как это
увидит ассистент.

- Модули логики: поиск человека, кэш профиля, сборка ответа
- MCP-эндпоинт на quiz-app с авторизацией по токену
- Три инструмента: кто ждёт ответа · найти человека и показать переписку ·
  что писать дальше
- Саша подключает его в Claude Code и гоняет на живых диалогах, промпт
  правится по его замечаниям

**Готово, когда** Саша подтверждает, что ответы похожи на то, что он написал
бы сам.

### Этап 2. Телеграм для ассистента

Та же логика, другой вход. Тонкая ветка в существующем боте quizapp, гейт по
telegram id ассистента.

**Готово, когда** ассистент пишет боту ник и получает текст сообщения.

## Архитектура

### Поток одного вопроса к суфлёру

```
«@nedosek_coach, что дальше?»
  │
  ├─ 1. кто это      findLeadByHandle(ник) → ig_lead → chat_id, воронка, статус
  │      не нашли    → «этот человек не из инсты, вставь переписку текстом»
  │
  ├─ 2. диалог       listChatMessages(chat_id, 40) → живьём, без кэша
  │
  ├─ 3. профиль      ig_profile: свежее недели → готовое
  │                  иначе → Apify → разбор моделью → пишем в ig_profile
  │
  ├─ 4. база         карта шести документов → выбор куска → чтение куска
  │
  └─ 5. ответ        готовый текст + строка обоснования + материал, если нужен
```

### Кэш профилей

Новая таблица `ig_profile`, ключ — ник.

```
username        TEXT PRIMARY KEY
followers       INTEGER
bio             TEXT
link            TEXT
posts_30d       INTEGER
formats         JSONB     -- сколько рилсов, каруселей, фото
summary         TEXT      -- ниша, о чём контент, есть ли кейсы и офферы
contradiction   TEXT      -- что в профиле спорит со словами человека
case_slug       TEXT      -- какой кейс Саши сюда ложится
scanned_at      TIMESTAMP(3)
```

Заводится скриптом `scripts/ig-profile-create-tables.mjs`.
**`prisma db push` на этой базе запрещён**, она общая с другими проектами.

Скан только по требованию: нет смысла тратить Apify на тех, кто не выходит на
контакт. Раз про человека спросили, контакт уже есть.

### База знаний живёт в таблице, не в коде

Шесть документов кладутся в БД и читаются оттуда. Иначе каждая правка
формулировки требует деплоя, а на этапе 1 Саша будет править их часто.

## Границы

**Бот не отправляет сообщения.** `chats_send_message` существует и работает
через официальный Instagram Messaging API, но граница между суфлёром и
автоотправкой не решена. Обе ветки только читают.

**Телеграм-переписки не видны.** ChatPlace покрывает инста-директ, канал
подтверждён. Для остального работает вставка текстом.

**Голосовые не разбираем.** У Саши голос уходит на два страха, и оба означают
«зовём Сашу».

## Модели и деньги

Ключ уже есть: `ANTHROPIC_API_KEY` из `brand-quiz/.env.local`, прописан в
quiz-app и в Vercel. Подписка не подходит, `claude -p` отвечает 1,5-2 минуты.

**Приоритет входящих и выбор материала — Haiku 4.5. Сам ответ — Sonnet 5.**
Текст уходит живому человеку от лица Саши, качество формулировок здесь важнее,
чем у бота для учеников.

На один вопрос суфлёра уходит около 9-10 тыс. токенов входа (инструкция, кусок
базы, 40 сообщений переписки, карточка профиля) и ~500 выхода.

| Модель | Вход / выход за 1M | Ответ без кэша | С кэшем | 50 вопросов в день |
|---|---|---|---|---|
| Haiku 4.5 | $1 / $5 | 1,2 ¢ | ~0,6 ¢ | 9-18 $/мес |
| Sonnet 5 | $2 / $10 | 2,4 ¢ | ~1,2 ¢ | 18-36 $/мес |

Разбор входящих дешевле на порядок: около 12 содержательных сообщений в день,
каждое короткое.

Кэш ставится на стабильную часть промпта: инструкция, карта, кусок базы.
Переписка и карточка идут после последней точки кэширования.

⚠️ Минимальный кэшируемый префикс у Haiku 4.5 — 4096 токенов. Ужмёшь стабильную
часть сильнее, и кэш отвалится молча, как уже было у бота по материалам.

## Ошибки

| Риск | Что делаем |
|---|---|
| ChatPlace отдаёт 500 на частых запросах | Повтор с растущей задержкой, пауза 150 мс между страницами. Уже реализовано в `chatplace.ts` |
| Обход всех чатов долгий | На 291 чат ушло около двух минут. Разбор входящих гоняется по расписанию, а не на открытие страницы |
| Apify упрётся в лимит бесплатного плана | Скан по требованию; при отказе отвечаем без профиля и говорим об этом |
| Первый вопрос про человека медленный | Сразу «смотрю профиль, минуту», ответ вторым сообщением |
| Модель начнёт дожимать | Запрет дожима в системном промпте, проверяется на eval |
| Приоритет ошибётся и утопит горячего лида | Список показывает и отсеянное тоже, отдельной вкладкой |

## Открытые вопросы

1. **Telegram id ассистента.** Нужен только на этапе 2.
2. **Лимит Apify на бесплатном плане.** Проверяется первым живым прогоном.
3. **Схемы оплаты.** В живых диалогах их семь, в документе про цены три.
   Пока помощник зовёт Сашу на всё, кроме трёх записанных.
4. **Личные ссылки на закрытые тарифы.** Пока их нет, помощник зовёт Сашу.
5. **Автоотправка.** Отложена, решение за Сашей.
