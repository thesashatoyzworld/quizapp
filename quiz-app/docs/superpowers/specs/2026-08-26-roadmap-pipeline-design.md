# Конвейер маршрутной карты: от оплаты до отправки без рук

**Дата:** 2026-08-26
**Бот:** @testtoyzbot (`quiz-app`, `src/app/api/telegram-webhook/route.ts`)
**Ветка:** `roadmap-autogen` (PR #47, не смёржен)
**Повод:** карта Михаила Коробицына 26.08 собиралась наполовину руками

## Цель

Человек оплатил, наговорил анкету, получил карту. Саша в этом участвует ровно
дважды: читает превью и говорит «отправляй» или наговаривает правки голосом.
Больше ничего руками не делается.

## Что уже работает

- Оплата т2 из бота: `sendWelcomeT2()` шлёт приветствие и запускает анкету.
- Оплата т3 из бота: заводит анкету, шлёт приглашение и преамбулу.
- Анкета т2 закрылась: `scheduleRoadmapBuild()` ставит сборку в QStash.
- Сборка: `buildSource → generateRoadmap → saveDraft → sendPreview`, ~2 минуты, ~$0.28.
- Кнопки под превью: одобрить, пересобрать, править в админке.
- `approveAndSend()`: открывает карту, шарит базовый набор строк, шлёт человеку
  сообщение со ссылкой. Проверен живьём дважды (Аня 24.08, Михаил 26.08),
  оба раза прогоном скрипта, потому что ветка не задеплоена.
- Страница вида клиента: `/admin/roadmaps/<slug>/preview?mode=defaults`.

## Что сломано или отсутствует

| Звено | Что не так | Как всплыло |
|---|---|---|
| Расшифровка | `transcribeTgVoice()` идёт в OpenAI, а там `credit_balance_exhausted` | У Михаила 9 голосовых, 0 расшифровок; ему 9 раз ушло «не разобрал запись» |
| Тишина при сбое | Расшифровка упала, Саше не сказали | Про пустую анкету узнали только при сборке карты, через день |
| Запуск сборки | Условие «трек анкеты = t2», а не «у человека тариф 2» | Михаил: анкета т3, тариф т2, карта сама бы не собралась |
| Превью | Четыре простыни текста в боте | «Мне надо видеть это так, как видит клиент» (24.08) |
| Правки | Только «пересобрать целиком» или SQL руками | Правки 26.08 применялись SQL-запросами |
| Память | Правка живёт один раз | «Услуги не продаются через воркшопы» придётся говорить каждый раз |

## Решения

### 1. Расшифровка: один модуль на анкету и зумы

Новый `src/lib/transcribe/`:

```
index.ts        transcribeAudio(buffer, filename, opts) → string
                провайдер из TRANSCRIBE_PROVIDER, по умолчанию elevenlabs
elevenlabs.ts   POST https://api.elevenlabs.io/v1/speech-to-text
                form-data: file, model_id=scribe_v2, language_code=rus
                заголовок xi-api-key
openai.ts       нынешний код whisper-1, остаётся запасным
```

`src/lib/whisper.ts` худеет до телеграм-части: `fileId → getFile → download →
transcribeAudio()`. Экспорт `transcribeTgVoice` и `TG_FILE_LIMIT_BYTES` сохраняется,
вызывающие не меняются.

Ключ уже есть: `agent-hub/zoom-drainer/.env`, `ELEVENLABS_API_KEY`. Проверен 26.08,
живой, скоуп урезан до транскрибации. Кладётся в Vercel env проекта quizapp.

Зум-пайплайн переезжает на этот же модуль отдельной задачей, здесь только общий
интерфейс, чтобы переезжать было куда.

### 2. Сбой расшифровки перестаёт быть тихим

`transcribePending()` при исключении:
- пишет `transcriptStatus = 'failed'` в `intake_answers` (новая колонка, дефолт `null`);
- шлёт человеку то же «не разобрал запись» (как сейчас);
- шлёт Саше одно сообщение на анкету, не на ответ: «у @user 3 голосовых без
  расшифровки, анкета придёт неполной». Дедуп по `intake_id` за последний час,
  иначе на девяти ответах Саша получит девять сообщений.

### 3. Добор перед сборкой

`buildSource()` перед чтением ответов: если есть `kind='voice'` с пустым `transcript`
и непустым `fileId`, пробует расшифровать ещё раз (последовательно, не более 20
ответов). Что не поднялось, идёт в `warnings` черновика и видно в превью.

Это лечит и прошлые анкеты: у Михаила расшифровки залиты руками, у следующего
поднимутся сами.

### 4. Сборка запускается по тарифу

В `src/lib/intake.ts` условие `trackContent(intake.track).productSlug === T2_PRODUCT_SLUG`
меняется на проверку доступа: `tiersForTelegram(telegramId).uroven >= 2`.

Тариф 3 карту сам не собирает: у них процесс через созвон 1-1, карта строится после
него командой `/karta_sobrat`. Это остаётся как есть.

### 5. Превью одним сообщением

`sendPreview()` вместо четырёх сообщений шлёт одно:

```
🗺 Карта @mikhail_korobitcyn собрана

Уровень 5 с дыркой на уровне 3: снимает пятый месяц, но по чужим видео.
Затык: «Снимать своё, а не переснятое чужое»
16 задач на 4 недели · 6 ступеней · предупреждений нет

[👀 Посмотреть глазами клиента]  ← ссылка на /admin/roadmaps/<slug>/preview?mode=defaults
[✅ Одобрить и отправить]
[🔄 Пересобрать]
[✏️ Править в админке]
```

Диагноз одной строкой берётся из заметки `kind='insight'` про уровень, затык — из
ступени со статусом `blocked`. Полный текст никуда не девается: он на странице.

`previewMessages()` остаётся для `roadmap-build-test.ts`, но в бота больше не идёт.

### 6. Правки голосом

**Как бот понимает, что это правка.** Саша отвечает (reply) на сообщение превью.
`reply_to_message.message_id` пишется в `roadmaps.preview_message_id` при отправке
превью, по нему и находится карта. Без reply правка не принимается: Саша пишет боту
и по другим поводам.

**Что происходит:**

1. Голосовое расшифровывается тем же модулем (текстом тоже можно, тогда без шага).
2. QStash ставит задачу `/api/roadmap-patch` с `{roadmapId, text}`, Саше сразу
   «принял, применяю» — обращение к модели идёт минуты, вебхук столько не живёт.
3. Модель получает: текущую карту целиком (json), каталог материалов человека,
   расшифровку правки. Отвечает вызовом инструмента `patch` со строгой схемой:

```
operations: [
  { op: 'task.update',   key, title?, why?, material?, week? }
  { op: 'task.add',      week, title, why, material? }
  { op: 'task.remove',   key }
  { op: 'step.update',   position, title?, status?, evidence? }
  { op: 'metric.upsert', key, label?, startValue?, currentValue? }
  { op: 'metric.remove', key }
  { op: 'text.update',   field: goal|periodGoal|clientIntro|takeaway, value }
  { op: 'rebuild',       instruction }
]
rules: [ { text, scope: 'once' | 'always' } ]
```

4. Код применяет операции по ключам. Не упомянутое не трогается. `material` модель
   называет как `section/slug`, ссылку собирает код — тот же запрет на выдуманные
   ссылки, что при сборке.
5. `rebuild` применяется отдельно: карта собирается заново, `instruction` уходит в
   промпт. Так обрабатывается «переделай весь месяц под услугу».
6. Новое превью с кнопками, счётчик версии в шапке: «версия 2, изменено 3 задачи».

**Ограничение.** Патч работает, только пока `client_visible = false`. У открытой
карты человек уже ставит галочки; `task.remove` и `task.add` их сместят. На открытой
карте бот отвечает «карта уже у человека, правь в админке».

### 7. Память правил

Новая таблица:

```prisma
model RoadmapCorrection {
  id         String   @id @default(uuid())
  roadmapId  String?  @map("roadmap_id")
  rawText    String   @map("raw_text")        // расшифровка того, что сказал Саша
  operations Json?                            // что применилось
  ruleText   String?  @map("rule_text")       // формулировка правила, если это правило
  scope      String   @default("once")        // once | always
  active     Boolean  @default(true)
  createdAt  DateTime @default(now()) @map("created_at")

  @@map("roadmap_corrections")
}
```

Правила со `scope='always'` и `active=true` подмешиваются в `SYSTEM` при каждой
сборке отдельным блоком:

```
## Правила, которые Саша уже проговорил

- Услуги не продаются через воркшопы про инфопродукты: диалоги и услуга это «Метод Мани Мейкера».
- ...
```

Модель сама помечает `scope`. Разделение простое: правка про этого человека это
`once`, правка про то, как собирать карты вообще, это `always`.

Команда `/karta_pravila` печатает список с номерами, `/karta_pravila_stop 3` гасит
третье (`active=false`). Удаления нет: история правок это тоже данные.

Таблица заводится скриптом `scripts/roadmap-corrections-create-table.mjs`, как
делались остальные таблицы карт. **Не `prisma db push`**: база общая, push сносит
чужие таблицы.

## Порядок работ

1. Модуль расшифровки плюс ElevenLabs, ключ в Vercel. Проверка: голосовое в анкету,
   расшифровка в базе.
2. Уведомление Саше при сбое, `transcriptStatus`, добор в `buildSource`.
3. Запуск сборки по тарифу.
4. Превью одним сообщением.
5. Смёржить PR #47 и проверить кнопки живьём на настоящей анкете.
6. Таблица правок, патч-инструмент, `/api/roadmap-patch`, приём reply голосом.
7. Память правил в промпте, `/karta_pravila`.

Пункты 1-5 доводят до конца то, что уже написано. 6-7 это новое.

## Проверка

Прогон целиком на живом человеке: оплата т2 (тестовым заказом) → анкета из двух
голосовых → карта собралась сама → превью в бота → голосовая правка «поменяй
материал во второй задаче» → версия 2 → «Одобрить и отправить» → карта в кабинете
и сообщение человеку.

До живого прогона: `scripts/roadmap-build-test.ts` для сборки и новый
`scripts/roadmap-patch-test.ts` для патча, оба без отправки.

## Чего в этой работе нет

- Кто оплатил картой на сайте и не зашёл в бота: анкета у него не стартует, пока он
  не нажмёт `/start paid_<token>`. Дыра известная, редкая, отдельной задачей.
- Ручные апгрейды тарифа (крипта, перевод) доступ не выдают: у Михаила `uroven-t2`
  проставлен руками 26.08. Тоже отдельно.
- Перевод зум-пайплайна на общий модуль расшифровки: здесь только интерфейс.
