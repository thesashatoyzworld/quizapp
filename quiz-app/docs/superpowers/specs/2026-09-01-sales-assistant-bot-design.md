# Помощник ассистенту в продажах: ветка бота

Дата: 2026-09-01. Статус: дизайн согласован, план не написан.

## End Goal

Ассистент ведёт переписки в инста-директе и в любой момент спрашивает бота в
телеграме «`@nedosek_coach`, что дальше?». Бот сам достаёт живую переписку,
сам достаёт разбор профиля этого человека, сверяется с базой продаж Саши и
отдаёт готовый текст следующего сообщения.

Ассистент не копирует переписку, не открывает профиль руками, не ищет ссылки.

## Success Criteria

- [ ] Вопрос по нику находит человека среди 4305 записей `ig_lead`
- [ ] Переписка подтягивается на момент вопроса, а не из копии
- [ ] Ответ содержит готовый текст сообщения, а не совет, что надо бы написать
- [ ] Разбор профиля тянется только для тех, про кого спросили
- [ ] Повторный вопрос про того же человека не гоняет Apify заново
- [ ] Человек не из инсты не ломает ветку: бот просит вставить переписку текстом
- [ ] Бот сам ничего никому не отправляет

## Архитектура

Одна новая ветка в существующем боте. Отдельного бота не заводим: клиент
ChatPlace, таблица лидов и механизм базы уже лежат в этом проекте.

### Поток одного вопроса

```
ассистент пишет «@nedosek_coach, что дальше?»
  │
  ├─ гейт: telegram id в списке ассистентов, иначе ветка не срабатывает
  │
  ├─ 1. кто это      findLeadByHandle(ник) → ig_lead → chat_id, воронка, статус
  │      не нашли    → «этот человек не из инсты, вставь переписку текстом»
  │
  ├─ 2. диалог       listChatMessages(chat_id, 40) → последние 40 сообщений, живьём
  │
  ├─ 3. профиль      ig_profile: свежее недели → берём готовое
  │                  иначе → Apify → разбор моделью → пишем в ig_profile
  │
  ├─ 4. база         карта шести документов → выбор куска → чтение куска
  │
  └─ 5. ответ        готовый текст + строка обоснования + материал, если нужен
```

### Новые модули

| Файл | Ответственность |
|---|---|
| `src/lib/sales/lead.ts` | Найти человека по нику или имени, отдать `chat_id`, воронку, статус, отметку про анкету |
| `src/lib/sales/profile.ts` | Кэш и обновление разбора профиля: чтение `ig_profile`, вызов Apify, разбор моделью |
| `src/lib/sales/answer.ts` | Сборка промпта из диалога, профиля и куска базы; обращение к модели |
| `src/lib/sales/ask.ts` | Ветка бота: гейт, разбор запроса, ошибки, логи |
| `src/content/sales-kb/` | Шесть документов базы, перенесённых из GSD-BRAND |

### Кэш профилей

Новая таблица `ig_profile`, ключ — ник.

```
username        TEXT PRIMARY KEY
followers       INTEGER
bio             TEXT
link            TEXT
posts_30d       INTEGER
formats         JSONB     -- сколько рилсов, каруселей, фото
summary         TEXT      -- разбор моделью: ниша, о чём контент, есть ли кейсы и офферы
contradiction   TEXT      -- главное поле: что в профиле спорит с тем, что человек говорит
case_slug       TEXT      -- какой кейс Саши сюда ложится
scanned_at      TIMESTAMP(3)
```

Таблица заводится скриптом `scripts/ig-profile-create-tables.mjs`.
**`prisma db push` на этой базе запрещён**, она общая с другими проектами.

Обновление: по требованию, если запись старше семи дней. Пачками ночью не
гоняем — нет смысла тратить Apify на тех, кто не выходит на контакт.

### Что бот отдаёт

Формат уже описан в инструкции проекта и не меняется:

1. готовый текст сообщения
2. одной строкой, почему именно так, со ссылкой на похожий случай из библиотеки

Плюс, если по ситуации нужен материал, ссылка из документа 5 и фраза Саши
при отправке.

## Границы

**Бот не отправляет сообщения.** `chats_send_message` в ChatPlace есть и
технически работает через официальный Instagram Messaging API, но решение о
том, где проходит граница между суфлёром и автоотправкой, отложено. Ветка
только читает.

**Телеграм-переписки бот не видит.** ChatPlace покрывает инста-директ. Для
всего остального работает вставка текстом, тот же разбор, тот же ответ.

**Голосовые не разбираем.** У Саши голос уходит на два страха, и оба означают
«зовём Сашу». Ветка сохраняет это правило.

## Ошибки и деньги

| Риск | Что делаем |
|---|---|
| ChatPlace отдаёт 500 на частых запросах | Повтор с растущей задержкой, как в синке лидов |
| Apify на бесплатном плане упрётся в лимит | Скан только по требованию; при отказе бот отвечает без профиля и говорит об этом |
| Первый вопрос про человека медленный (Apify 30-60 с) | Бот сразу пишет «смотрю профиль, минуту», ответ вторым сообщением |
| Стоимость выше, чем у бота для учеников | См. расчёт ниже. Логи `cents` в `events`, как в `kb_question` |
| Модель начнёт дожимать | Запрет дожима уже в инструкции, выносим в системный промпт ветки и проверяем на eval |

## Модели и деньги

Ключ уже есть: `ANTHROPIC_API_KEY` из `brand-quiz/.env.local`, прописан в
quiz-app и в Vercel. Подписка не подходит, `claude -p` отвечает 1,5-2 минуты.

**Выбор материала — Haiku 4.5. Сам ответ — Sonnet 5.** Текст уходит живому
человеку от лица Саши, качество формулировок здесь важнее, чем у бота для
учеников, где задача найти урок и пересказать.

На один вопрос уходит около 9-10 тыс. токенов входа (инструкция, кусок базы,
40 сообщений переписки, карточка профиля) и ~500 выхода.

| Модель | Вход / выход за 1M | Ответ без кэша | С кэшем | 50 вопросов в день |
|---|---|---|---|---|
| Haiku 4.5 | $1 / $5 | 1,2 ¢ | ~0,6 ¢ | 9-18 $/мес |
| Sonnet 5 | $2 / $10 | 2,4 ¢ | ~1,2 ¢ | 18-36 $/мес |

Кэш ставится на стабильную часть промпта: инструкция, карта, кусок базы.
Переписка и карточка идут после последней точки кэширования, потому что
меняются от вопроса к вопросу.

⚠️ Минимальный кэшируемый префикс у Haiku 4.5 — 4096 токенов. Ужмёшь стабильную
часть сильнее, и кэш отвалится молча, как это уже было у бота по материалам.

## Открытые вопросы

1. **Telegram id ассистента.** Нужен для гейта, у Саши.
2. **Лимит Apify на бесплатном плане.** Проверяется первым живым прогоном.
3. **Схемы оплаты.** В живых диалогах их семь, в документе про цены три.
   Пока бот зовёт Сашу на всё, кроме трёх записанных.
4. **Личные ссылки на закрытые тарифы.** Пока их нет, бот зовёт Сашу.
